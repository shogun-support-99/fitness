# AGENTS.md

IronLog is a dependency-free, offline-first strength-training log: a static site with a marketing page (`index.html`, `assets/`) and the app (`app/`). No backend, no runtime build step, no runtime dependencies. See `README.md` for the product overview and `NOTICE` for licensing.

## Run and verify

- Serve the repository root over HTTP (README: `python3 -m http.server 8080`); open `/` for the landing page and `/app/` for the app. Do not use `file://` — ES module imports and the catalogue `fetch()` fail. On Windows, `python3` may only be a Store alias; use any available static server.
- `npm test` — full Node test suite (`node --test "tests/*.test.js"`), no install required.
- `node --test tests/stats.test.js` — one suite file. Add `--test-name-pattern="..."` to focus a test.
- `npm run check` — verifies every local `href`/`src` in HTML resolves.
- CI also runs `node --check` on every `.js` under `app/`, `assets/`, and `scripts/`. There is no lint, format, or typecheck script.
- After changing Tailwind classes, `src/tailwind.css`, or `tailwind.config.js`: `npm install && npm run build:css`, then commit the regenerated `assets/css/tailwind.css`. That compiled file is shared by the landing page and app, served directly, and **not** freshness-checked by CI.
- After changing anything under `src/scene/` or `src/components/` (the hero 3D scene), run `npm run build:scene` then commit the regenerated `assets/js/scene3d.js`. The bundle is committed so GitHub Pages serves it directly with no runtime build step. `assets/models/golem.glb` is the owner-supplied source character; do not regenerate or replace it without the owner's approval.

## Architecture

- Views in `app/js/views/` return HTML strings. `app/js/main.js` owns state, the render loop, and one delegated listener keyed on `data-action`. Add behavior to the `actions` map there, not with per-view listeners.
- Re-renders replace `#view-outlet` via `innerHTML`. Preserve focus with `data-focus-key`; search and timer paths patch the DOM directly so inputs are not rebuilt mid-typing.
- Escape every user-supplied string with `esc()` from `app/js/ui.js` before it reaches `innerHTML`; an XSS regression test enforces this.
- Use relative URLs only. The app runs at `/fitness/app/` on GitHub Pages and at `/` locally.
- `app/js/store.js` owns one `ironlog.v1` localStorage document at `SCHEMA_VERSION = 1`. Additive settings merge safely; breaking shape changes need an explicit migration in `#read()`.
- Exercise IDs are embedded in saved workout history. Do not change `makeExerciseId()` or the `ds-` ID convention without migrating stored data.
- `Store` and `RestTimer` take injected storage/clock so they run under Node; keep DOM access out of those modules.
- `artifacts/` holds ad-hoc debug/test scripts, not shipped app code.

## Generated data, media, and licensing

- `app/data/*.json` and `app/media/gymvisual/*` are generated by `node scripts/build-exercise-data.mjs --source /path/to/exercises-dataset`. Do not hand-edit them; regenerate and rerun tests.
- Dataset data is MIT; Gym Visual media is separately licensed. Preserve `NOTICE`, `catalogue-meta.json`, and each record's `media` and attribution fields.
- CI allows binary media only under `assets/img/`, `app/icons/`, and `app/media/gymvisual/`. Do not commit screenshots or debug images elsewhere.

## PWA and deploy

- `app/sw.js` precaches the app shell with stale-while-revalidate. After changing shell CSS/JS, bump `CACHE` (`ironlog-shell-vN`) and add any new shell files to `PRECACHE`; otherwise returning visitors get one stale load.
- Every push to `main` runs tests, syntax checks, link checks, and media/licensing guards, then deploys to GitHub Pages. Pull requests run the test job only. There is no manual deploy.
- `.agents/skills/` contains development-only design skill packs (see `NOTICE`); it is not app code. `scripts/setup-github.sh` is a one-shot `gh`-authenticated repo/profile makeover — do not run it for routine setup.

## Required git workflow

At the end of every completed task, automatically:

1. Run `git add .`
2. Create a clear, descriptive commit message covering the change.
3. Run `git push origin main`

Do this without waiting for approval. Never leave completed work uncommitted or unpushed. If a step fails (auth, non-fast-forward, no remote), report the exact failure rather than silently skipping it.
